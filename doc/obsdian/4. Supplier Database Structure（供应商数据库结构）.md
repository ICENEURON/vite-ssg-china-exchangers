# Supplier Database Structure / 供应商数据库结构

Last updated: 2026-05-08.

This note summarizes the current Supabase-facing supplier database model. The complete maintainer reference is now folded into `doc/project-structure.md`.

## English

### Data Layer Pattern

Supplier and product data is maintained in Supabase, exported to `src/data/*.json`, converted into localized JSON under `src/locales/{en,zh}`, and then statically rendered by vite-react-ssg.

The browser does not query manufacturer/product tables directly. It reads generated locale JSON.

### Tables Exported by `pnpm sync`

| Table | Role |
| --- | --- |
| `countries` | Country dictionary exported as `id`, `name`, `name_zh`. |
| `industries` | Industry dictionary with localized `name`. |
| `manufacturers` | Manufacturer profile source table. |
| `manufacturer_assets` | Manufacturer-level media, certificates, customer logos, and documents. |
| `products` | Product source table linked to manufacturers. |
| `product_assets` | Product gallery images, certificates, and documents. |

`rfqs` is not exported by sync scripts.

### Asset Tables

Common fields for `manufacturer_assets` and `product_assets`:

- `id`
- relation id: `manufacturer_id` or `product_id`
- `asset_type`
- `alt_text`
- `storage_bucket`
- `storage_path`
- `file_name`
- `file_type`
- `order`
- `created_at`
- `updated_at`

The active Storage bucket is `assets`. Frontend URLs are generated as:

```text
/storage/{storage_bucket}/{storage_path}
```

Typical URL:

```text
/storage/assets/{manufacturer-slug}/{folder}/{file-name}
```

### Asset Type Mapping

Manufacturer generator supports:

| Frontend output | Accepted asset types |
| --- | --- |
| `certifications` | `certifications`, `certificate` |
| `customers` | `customers`, `logo` |
| `images` | `images`, `media` |
| `documents` | `document` |

Product generator supports:

| Frontend output | Accepted asset types |
| --- | --- |
| `images` | `gallery_image`, fallback `image` |
| `certificates` | `certificate` |
| `documents` | `document` |

### Importer

`supabase_importer/import.js` imports local JSON and local assets into Supabase. It uses `supabase_importer/data/sync_config.json` as the whitelist of active manufacturer slugs.

Important: importer cleanup can delete DB rows and Storage objects that are missing from the whitelisted local payload. Review data before running it with a production service role key.

## 中文

### 数据层模式

供应商和产品数据在 Supabase 中维护，通过 `pnpm sync` 导出为 `src/data/*.json`，再转换为 `src/locales/{en,zh}` 下的本地化 JSON，最后由 vite-react-ssg 静态渲染。

浏览器不会直接查询厂家/产品表，而是读取生成后的 locale JSON。

### `pnpm sync` 导出的表

| 表 | 作用 |
| --- | --- |
| `countries` | 国家字典，只导出 `id`、`name`、`name_zh`。 |
| `industries` | 行业字典，包含多语言 `name`。 |
| `manufacturers` | 制造商资料主表。 |
| `manufacturer_assets` | 厂家级图片、证书、客户 Logo 和文档。 |
| `products` | 产品主表，关联制造商。 |
| `product_assets` | 产品图片、证书和文档。 |

`rfqs` 不会被同步脚本导出。

### `manufacturers`

当前字段：

- `id`
- `name`
- `short_description`
- `full_description`
- `advantages`
- `slug`
- `website`
- `email`
- `phone`
- `country_id`
- `country_name`
- `city`
- `address`
- `established_year`
- `factory_area`
- `employee_count`
- `industries`
- `export_markets`
- `is_visible`
- `seo_data`
- `video_link`
- `social_media_links`
- `created_at`
- `updated_at`

可本地化字段通常以 JSON 对象保存，一般包含 `en` 和 `zh` 键。

### 资产表

- `id`
- 关联 id：`manufacturer_id` 或 `product_id`
- `asset_type`
- `alt_text`
- `storage_bucket`
- `storage_path`
- `file_name`
- `file_type`
- `order`
- `created_at`
- `updated_at`

当前 Storage bucket 为 `assets`。前端 URL 生成规则：

```text
/storage/{storage_bucket}/{storage_path}
```

典型 URL：

```text
/storage/assets/{manufacturer-slug}/{folder}/{file-name}
```

### 资产类型映射

厂家生成器支持：

| 前端输出 | 接受的 asset_type |
| --- | --- |
| `certifications` | `certifications`, `certificate` |
| `customers` | `customers`, `logo` |
| `images` | `images`, `media` |
| `documents` | `document` |

产品生成器支持：

| 前端输出 | 接受的 asset_type |
| --- | --- |
| `images` | 优先 `gallery_image`，回退 `image` |
| `certificates` | `certificate` |
| `documents` | `document` |

### 导入器

`supabase_importer/import.js` 将本地 JSON 和本地资产导入 Supabase，并使用 `supabase_importer/data/sync_config.json` 作为有效厂家 slug 白名单。

注意：导入器清理逻辑可能删除白名单 payload 中缺失的数据库记录和 Storage 文件。使用生产 service role key 运行前必须检查数据。
