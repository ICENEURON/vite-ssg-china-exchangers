# RFQ Specification / 询价数据结构

Last updated: 2026-05-08.

This document describes the RFQ behavior currently implemented in code.

## English

### Current Frontend Flow

The RFQ page is implemented at `src/pages/rfq/index.tsx` with these steps:

1. Project context.
2. Thermal and equipment design parameters.
3. Email OTP verification through Supabase Auth.
4. Final confirmation and submit.

### Step 1: Project Context

Fields collected:

- `firstName`
- `lastName`
- `companyName`
- `country`
- `industry`
- `customIndustry` when industry is `other`

### Step 2: Technical Parameters

The current RFQ form captures:

- Hot and cold media names.
- Inlet and outlet fluid phase types.
- Inlet and outlet mass flow.
- Gas phase fraction when a gas-liquid phase is selected.
- Inlet and outlet temperatures.
- Inlet and outlet density.
- Inlet and outlet specific heat.
- Inlet and outlet conductivity.
- Inlet and outlet viscosity.
- Heat load.
- Plate material and optional custom material.
- Design pressure and test pressure.
- Hot/cold design temperature.
- Hot/cold flange standard and optional custom standard.
- Additional notes.

### Step 3: Email Verification

The form uses Supabase Auth email OTP helpers:

- `sendVerificationOTP(email)`
- `verifyOTPCode(email, token)`

Successful OTP verification creates or confirms a Supabase Auth session and allows the user to continue.

### Step 4: Submit Payload

`submitRFQ` inserts into `rfqs` with this payload shape:

| Column | Source |
| --- | --- |
| `first_name` | `contextData.firstName` |
| `last_name` | `contextData.lastName` |
| `company_name` | `contextData.companyName` or `null` |
| `country` | `contextData.country` |
| `email` | Verified email, lowercased |
| `is_business_email` | Derived by checking common free email domains |
| `industry` | Selected industry id or custom industry string |
| `additional_notes` | Notes or `null` |
| `is_stealth` | Anonymous mode boolean |
| `parameters` | JSON object containing the technical parameters |

### Business Email Detection

The current free-domain list includes:

- `gmail.com`
- `yahoo.com`
- `hotmail.com`
- `outlook.com`
- `qq.com`
- `163.com`
- `126.com`
- `foxmail.com`
- `icloud.com`

Emails outside this list are currently treated as business emails.

### Not Implemented Yet

The following are not currently implemented in code:

- Automatic manufacturer matching.
- Automatic RFQ email dispatch to suppliers.
- `manufacturers_sent_list` population.
- File attachments.
- Supplier response tracking.
- Buyer-side RFQ dashboard.

## 中文

### 当前前端流程

RFQ 页面位于 `src/pages/rfq/index.tsx`，当前包含四步：

1. 项目背景。
2. 热工和设备设计参数。
3. 通过 Supabase Auth 进行邮箱 OTP 验证。
4. 最终确认并提交。

### 第一步：项目背景

采集字段：

- `firstName`
- `lastName`
- `companyName`
- `country`
- `industry`
- 当行业为 `other` 时使用 `customIndustry`

### 第二步：技术参数

当前 RFQ 表单采集：

- 热侧和冷侧介质名称。
- 入口和出口流体相态。
- 入口和出口质量流量。
- 当选择气液相态时填写气相分率。
- 入口和出口温度。
- 入口和出口密度。
- 入口和出口比热。
- 入口和出口导热系数。
- 入口和出口粘度。
- 热负荷。
- 板片材料和可选自定义材料。
- 设计压力和试验压力。
- 热侧/冷侧设计温度。
- 热侧/冷侧法兰标准和可选自定义标准。
- 补充备注。

### 第三步：邮箱验证

表单使用 Supabase Auth 邮箱 OTP：

- `sendVerificationOTP(email)`
- `verifyOTPCode(email, token)`

验证成功后，用户可以进入最终确认步骤。

### 第四步：提交 Payload

`submitRFQ` 向 `rfqs` 插入以下结构：

| 字段 | 来源 |
| --- | --- |
| `first_name` | `contextData.firstName` |
| `last_name` | `contextData.lastName` |
| `company_name` | `contextData.companyName` 或 `null` |
| `country` | `contextData.country` |
| `email` | 已验证邮箱，小写化 |
| `is_business_email` | 根据常见免费邮箱域名判断 |
| `industry` | 所选行业 id 或自定义行业文本 |
| `additional_notes` | 备注或 `null` |
| `is_stealth` | 匿名模式布尔值 |
| `parameters` | 包含技术参数的 JSON 对象 |

### 企业邮箱判断

当前免费邮箱域名列表：

- `gmail.com`
- `yahoo.com`
- `hotmail.com`
- `outlook.com`
- `qq.com`
- `163.com`
- `126.com`
- `foxmail.com`
- `icloud.com`

不在该列表中的邮箱目前会被视为企业邮箱。

### 尚未实现

以下能力当前代码尚未实现：

- 自动匹配制造商。
- 自动向供应商发送 RFQ 邮件。
- 写入 `manufacturers_sent_list`。
- 文件附件。
- 供应商回复追踪。
- 买家侧 RFQ 仪表盘。
